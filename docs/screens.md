# book-universe / 화면 흐름 v0.2 — 1단계 범위: 도서관 소장자료(Pyxis)

> **현재 구현 상태 (2026-09-16)**
> 아래는 설계다. 실제 앱은 순서를 바꿔 **전체 유니버스를 먼저 세웠다.**
>
> | 화면 | 상태 |
> |---|---|
> | 전체 유니버스 | ✅ `/` — 도서관 내 서재 실데이터 스냅샷으로 동작 |
> | 내 서재 | ❌ 삭제 (2026-09-16). 아래 설계는 남겨두지만 구현은 없다 |
> | 내 위치 오버레이 | ⏸ 개인 데이터가 서버에 없어서 아직 불가 |
>
> 유니버스를 먼저 세운 이유: 설계의 전제("겹침이 실제로 생기는가")를
> 도서관에 이미 있는 내 서재 데이터로 바로 검증할 수 있었기 때문이다.
>
> 개인 계층(내 서재 · 내 위치)은 구현을 걷어냈다. 아래 설계는 그 방향으로
> 돌아갈 때의 참고로 남긴 것이고, 지금 제품은 유니버스 한 화면이다.


화면은 3개, 그리고 그 사이를 잇는 전이 2개가 전부다.

| # | 화면 | 좌표계 | 보는 사람 | 렌더러 |
|---|---|---|---|---|
| 1 | **내 서재** (개인 별자리) | 내가 정한 좌표, 영구 고정 | 본인만 | SVG / DOM |
| 2 | **전체 유니버스** | 서버 사전계산 좌표 | 누구나 | WebGL (PixiJS) |
| 3 | **내 위치** (2번 위의 레이어) | 2번과 동일 | 로그인한 본인에게만 | 2번과 같은 캔버스 |

3번은 별도 화면이 아니라 2번 위에 얹는 레이어다. 좌표를 새로 계산하지 않고
"내 work_id 집합"으로 색만 바꾸므로 쿼리 한 줄, 레이어 하나면 된다.

## 화면 1 · 내 서재

```
┌──────────────┬────────────────────────────────┬──────────────┐
│ 검색 패널     │          캔버스                 │  인스펙터     │
│  320px       │   (SVG, pan/zoom, 드롭 타깃)     │  360px        │
│              │                                 │  (선택 시만)  │
│ [자료유형▾]   │      ○───────○                  │              │
│ ┌──────────┐ │       \     /                   │  서지정보     │
│ │ 검색결과  │ │        \   /                    │  판본 전환    │
│ │  카드    │─┼──드래그──▶ ○                     │  [대출 현황] │
│ │  카드    │ │                                  │  [판본제안]  │
│ └──────────┘ │  ┌─────┐                        │  내 메모      │
│              │  │미니맵│         [별자리 탭 ▾]  │  태그 / 색    │
└──────────────┴──└─────┘────────────────────────┴──────────────┘
```

### 검색 → 드래그 → 등록

0. 자료유형 필터 옵션은 `GET /pyxis-api/1/material-types` 로 채운다. **하드코딩 금지.**
   `CR 연속간행물` 은 목록에서 뺀다 — 저널은 별이 되지 않는다.
1. 검색어 입력 → **400ms 디바운스** → `GET /api/search?q=&material=`
   자동완성은 Pyxis `auto-completions/{q}` 를 그대로 쓴다
2. 서버 프록시가 Pyxis 호출 → 결과 정규화 → **같은 쿼리 24h 캐시**
   Pyxis 는 우리 시스템이지만 타이핑마다 때릴 이유가 없다. 프록시를 끼워두면
   2단계에서 EDS 를 붙일 때 클라이언트 코드를 건드리지 않게 된다
3. 결과 카드 표시: 제목 / 저자·연도 / 자료유형 배지 / 대출 가능 여부
4. 카드를 캔버스로 드래그 → 드롭 지점의 캔버스 좌표 획득
5. **낙관적 렌더**: 드롭 즉시 회색 노드를 그 자리에 배치 (서버 응답 대기 X)
6. `POST /api/nodes { sourceRef, x, y, constellationId }`
7. 서버가 **resolve 파이프라인** 실행 (아래)
8. 응답 도착 → 회색 노드가 실제 데이터로 채워지며 **별 점화 애니메이션**
   실패 시 노드가 스르륵 사라지고 토스트

### resolve 파이프라인 (서버) — 1단계

소장자료만 다루므로 단순하다. 단일 도서관 목록이라 한 자료 = 한 레코드이고,
Pyxis id 로 1:1 이 성립한다. **유사도 매칭은 켜지 않는다.**

```
Pyxis 검색 결과 카드
   │
   ├─ 식별자 추출·정규화   isbn13 (있으면) + pyxis:pnu (항상)
   │
   ├─ work_identifiers 조회
   │     ├─ HIT  → 기존 별에 합류                  ... 이미 누가 등록한 자료
   │     └─ MISS → GET /biblios/{id} 로 MARC 상세 조회
   │                 └─ works 1 + editions 1 생성   ... 새 별
   │
   └─ access_links 기록 (청구기호·소장처·대출상태) → 노드 생성
```

같은 자료를 두 사람이 등록하면 `isbn13` 또는 `pyxis:pnu` 가 충돌하면서
자동으로 같은 별에 모인다. 이게 겹침의 전부다 — 1단계에서는 애매한 판정이 없다.

### 2단계에 되살아나는 것

판본이 다른 레코드(『인공지능』 2018년판 / 2025 개정판)는 Pyxis 에 별개로 존재해서
1단계에서는 별개의 별이 된다. 이걸 묶는 건 2단계다.

그때 `needs_confirm` 상태가 들어온다 — 유사도 0.65~0.85 구간의 노드가 캔버스에
**점선 테두리**로 뜨고 "혹시 같은 책인가요?" 를 묻는다. 확정 전까지 전역 집계에
들어가지 않는다. 1단계에는 이 상태가 없다.

그 전까지는 인스펙터에 **[이 책은 저 별과 같은 책이에요]** 버튼만 두어
사용자 제안을 모아둔다. 2단계에서 켤 때의 검증 데이터가 된다.

### 연결 그리기

1. 노드 호버 → 테두리에 앵커 4개 표시
2. 앵커를 드래그 → 고무줄 선이 따라옴
3. 다른 노드 위에 드롭 → **관계 타입 팝오버**
   `인용함 / 반박함 / 같은주제 / 방법론차용 / 후속연구` + 라벨 입력(선택)
4. `Esc` 로 언제든 취소

관계 타입은 5개 고정이다. 자유 입력을 허용하면 전역 집계가 불가능해진다.

### 저장

| 동작 | 저장 방식 |
|---|---|
| 노드 이동 | 드래그 종료 후 500ms 디바운스, 여러 노드 묶어서 `PATCH /api/nodes` |
| 선 생성/삭제 | 즉시 |
| 메모 편집 | 1s 디바운스 |
| pan/zoom | 이동 종료 후 `constellations.viewport` 갱신 |

오프라인/실패 대비 로컬 큐를 두고 재접속 시 flush.

### 인스펙터 (노드 선택 시)

- 서지정보 (제목 / 저자 / 연도 / 학술지·출판사)
- **[대출 현황]** → 청구기호 `SDM 006.3 오51ㅇ` / 소장처 / 대출 가능 여부
- **[도서관에서 보기]** → Pyxis 상세 페이지 (`access_links`)
- **[이 책은 저 별과 같은 책이에요]** → 판본 묶기 제안 수집. 2단계에서 켤 때의 검증 데이터
- 판본 드롭다운 — 2단계부터. 1단계는 Work 1개에 Edition 1개뿐이라 항목이 하나다
- 내 메모 (마크다운) · 태그 · 색  ← 전부 비공개
- **[우주에서 보기]** → 화면 2로 전이

### 그 외

- 미니맵 (우하단)
- 자동 정렬 도우미: `연도순` / `주제별 뭉치기` — **실행취소 가능해야 함**. 내 배치를 파괴하는 기능이다
- 별자리 여러 개 (탭): "석사논문 서베이", "취미 독서" 등
- 단축키: `Space+드래그` 팬, `Del` 삭제, `Cmd/Ctrl+Z` 실행취소, `F` 전체 맞춤

## 화면 2 · 전체 유니버스

로그인 없이도 볼 수 있다. 여기에는 누구의 신원도 없다.

### LOD (줌 3단계)

| 단계 | 보이는 것 |
|---|---|
| **L0 멀리** | 성단 덩어리 + 성단 이름. 개별 별은 점으로만 |
| **L1 중간** | 별 + 굵은 연결선(weight_class 3↑). 상위 등급 별만 제목 표시 |
| **L2 가까이** | 모든 별 제목, 모든 연결선, 관계 타입 색 구분 |

### 시각 문법

| 시각 요소 | 데이터 |
|---|---|
| 별 밝기·크기 | `magnitude` (1~5 구간화된 등급. 원시 등록자 수는 내려오지 않는다) |
| 별 색 | 연도 (신간=청색, 오래됨=적색 — 실제 항성 색온도 은유) |
| 선 굵기 | `weight_class` |
| 성단 색 | `clusters.color` |

### 별 클릭 → 우측 패널

**보이는 것**: 서지정보, 등급, 소속 성단, 연결된 별 목록, `[도서관에서 보기]`,
`[내 별자리에 담기]`, 그리고 등록자 수는 **3명 이상일 때만** "47명이 이 별을 담았습니다"

**보이지 않는 것**: 누가 담았는지, 누가 어떤 선을 그었는지, 남의 메모 — 어떤 경로로도.

### 검색 / 필터

- 우주 내 별 검색 → 해당 별로 카메라 이동 + 하이라이트
- 필터: 자료유형(단행본 · 학위논문 · 보고서 · 고서 · 미디어), 연도 범위, 성단

## 화면 3 · 내 위치 (로그인 시)

화면 2의 우상단 토글 **[내 별자리 보기]**.

### 렌더 스택

```
 ① 전역 별      (흐린 백색, 균일)              ← 로그인 없이도
 ② 전역 연결선  (3명 이상, 굵기 = weight_class) ← 로그인 없이도
 ─────────────────────────────────────────────
 ③ 내 별 하이라이트 (색 점화 + 글로우)          ← 로그인 시, 클라이언트 계산
 ④ 내 연결선       (선명한 실선)               ← 로그인 시
 ⑤ 나만 보이는 미점화 별 (희미한 점 + 배지)      ← k 임계 미달인 내 별
```

③④는 `my_overlay_works` / `my_overlay_edges` 를 받아 `Set` 조회로 끝난다.
좌표는 전역 것을 그대로 쓴다.

⑤는 전역에 좌표가 없다 → **내가 그 별과 이어놓은 다른 별들(전역에 있는 것)의
무게중심 근처**에 띄운다. 배지: "아직 당신만 보고 있는 별".

### 진입 연출

토글 ON →
회색 우주에서 **내 별들만 색이 차오르고**, 카메라가 내 별들의 무게중심으로
부드럽게 이동(easing 1.2s). 하단에 한 줄: **"당신의 하늘은 여기입니다."**

### 사이드 패널

```
내 별          128개
  ├ 우주 등재   91개
  └ 나만의 별   37개        ← 아직 아무도 같이 보지 않는 별
걸친 성단      4개  (기계학습 / 인지과학 / 과학철학 / 통계)
```

### 파생 기능 2개

- **한 칸 옆** — 내 별과 연결돼 있는데 내게 없는 별 상위 10개.
  이 서비스에서 가장 설득력 있는 추천이다.
- **겹침** — "당신과 12개의 별을 공유하는 사람이 3명 있습니다"
  (k>=3 충족 시에만. 익명을 유지하면서 연결감을 준다)

## API 경계

이 표가 프라이버시 설계의 최종 점검표다.

| 엔드포인트 | 인증 | 반환 | 신원 포함 여부 |
|---|---|---|---|
| `GET /api/search` | 교내 인증 | 도서관 검색 결과 | 해당 없음 |
| `POST /api/nodes` | 필요 | 생성된 내 노드 | 내 것만 (RLS) |
| `PATCH /api/nodes` | 필요 | - | 내 것만 (RLS) |
| `GET /api/universe` | **불필요** | `universe_works` + `universe_edges` + `layout_positions` | **구조적으로 불가능** (매트뷰 컬럼에 없음) |
| `GET /api/me/overlay` | 필요 | 내 work_id 목록 + 내 엣지 | 내 것만 (RLS) |

`/api/universe` 가 신원을 흘릴 방법이 없다는 것이 핵심이다.
애플리케이션 코드가 아니라 매트뷰의 컬럼 목록이 그걸 보장한다.

## 구현 순서

| 단계 | 범위 | 확인 지점 |
|---|---|---|
| 1 | 화면 1 + **Pyxis 어댑터** + resolve(1:1) | 드래그해서 별을 놓는 게 재미있는가 |
| 2 | 매트뷰 2개 + 배치 레이아웃 + 화면 2 | 군집이 눈에 보이기 시작하는가 (50명이 분기점) |
| 3 | 화면 3 오버레이 + 파생 기능 2개 | "내 하늘" 순간이 먹히는가 |
| 4 | 판본 묶기(유사도 ON) + 성단 이름 투표 | 판본이 합쳐지면 겹침이 더 선명해지는가 |
| 5 | EDS 편입 (학술논문) · 웹문서 등록 | 범위를 넓힐 값이 확인됐는가 |

1단계에서 화면 2를 안 만들어도 데이터는 이미 쌓인다.
매트뷰는 나중에 얹어도 그동안의 등록이 전부 반영된다.

**1단계에는 외부 의존이 하나도 없다.** Pyxis 는 우리 도메인이고 자격증명이 필요 없다.
EBSCO EDS 자격증명은 5단계에 가서야 필요해진다.
